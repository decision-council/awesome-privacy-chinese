# 数据与隐私合规资料库(可核验)

本目录是 [awesome-privacy-chinese](../README.md) 的法规子库,专做一件主仓 README 的链接清单做不到的事:**把法规原文归档下来,并让每一条归纳都能被程序验证。**

> 更新至 **2026-08 · 北京时间**。资料汇编,**不是法律意见**;以官方原文为准。

## 为什么要有这一层

主仓 README 的「重要国内法规和条例」是链接清单——好用,但链接会失效、内容会改版、而且看不出整理者是不是真读过原文。这里补上三件事:

1. **原文归档**:75 份官方来源(法律、行政法规、部门规章、网信办通报、TC260 文件)连原始字节一起存在仓内,记录取回时间与 **sha256**(原始字节与抽取文本各一份摘要)。链接哪天失效,内容还在;归档被人改过,校验会红。
2. **引文可核验**:文档里每条事实都附一段来源原文的逐字引文,**135 条引文 + 61 处数量口径由脚本逐字比对归档**。改一个字 CI 就红。
3. **机读义务表**:84 条可执行义务(门槛/期限/备案/豁免/罚则),可按类型和主题筛选。

**脚本保证什么、不保证什么**:脚本校验「引文确实逐字存在于归档原文」与「摘要里的数量与原文一致」;**引文与摘要的语义对应关系是人工核对的**。尚未取得归档佐证的条目一律标 ⚠️,并写明「这条我能不能自己查」。

## 快速开始

```bash
cd compliance

# 离线复核(推荐先跑这个):不联网、不装依赖,秒级校验 75 份归档与 135 条引文
python3 scripts/validate.py

# 看监管又发了什么(联网,访问 cac.gov.cn)
python3 scripts/discover_sources.py

# 仅在新增/刷新来源时运行(联网;会重写 sources/MANIFEST.json)
python3 scripts/fetch_sources.py --only <source-id>
```

归档已随仓提交,**克隆后无需下载任何东西**即可完整复核。

## 数据纪律

1. **无官方来源不进库**——每条事实可追到 `sources/` 里一份归档原文。
2. **区分发布日、签署日与施行日**——三者常被合写,是错误高发区。
3. **征求意见稿绝不当已发布规则引用**——标 `draft_for_comment`。
4. **口径冲突并列标注,不私自二选一**——例:2025 年 App 通报数量,官方口径「1100 余款」与行业梳理口径「近 4000 款」并存,差异源于是否合并各部委/地方/SDK 统计。
5. **未取得原文佐证的一律标 ⚠️**,不为了完整而编。
6. **一切时间为北京时间(UTC+8)**。

校验由 `scripts/validate.py` 自动执行,CI 在每个 PR 上重跑——违反上述规则会直接挡住合并。

## 已知局限(别当它不存在)

- **标准正文未归档**:GB/T 43697-2024 与 GB/T 45654-2025 只归档了标准平台的检索条目页(含标准号与发布/实施日),**不含条文**。涉及标准条款的表述一律标 ⚠️。
- **广泛流传的量化阈值未经核实**:GB/T 45654 的「不良信息比例 ≤5%」「合格率 ≥90%」在本库无任何归档佐证,不要直接写进产品验收线。
- **部分名单以图片发布**:合规审计认证机构两批名单的逐家机构名称在原文中是图片,纯文本归档只留下了数量。

更多见 [MAINTENANCE.md](MAINTENANCE.md)。
