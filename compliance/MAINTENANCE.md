# 维护说明

这份文档说明本库**怎么保持不过时**,以及一个陌生人接手要知道什么。

## 一、更新一轮的标准流程

```bash
# 1. 看监管又发了什么(枚举,不是搜索)
python3 scripts/discover_sources.py --json /tmp/new.json

# 2. 把值得收的加进 scripts/sources.json,然后归档
python3 scripts/fetch_sources.py

# 3. 核对 sources/MANIFEST.json 的 served_title——政府站点会对错误路径返回 200 + 门户首页
# 4. 把新文件里的义务写进 data/,每条附 sources/text/ 里的逐字引文
python3 scripts/validate.py       # 全绿才提交
```

`discover_sources.py` 爬的是网信办「数据专栏」的八个专题索引页。**这比关键词搜索可靠**:索引页里的东西就是监管自己认定属于该主题的文件,不会因为你想不到某个说法就漏掉。

## 二、为什么用枚举而不是搜索

搜索找法规是逐个找,靠你先想到它存在。第一轮用搜索建库时,整类文件被漏掉了——包括当时刚施行的《网络数据安全风险评估办法》和给出境认证路径正式依据的《个人信息出境认证办法》。改成枚举专题索引后,一次列出 80 篇未收录文件。

两个坑写进了爬虫注释,因为它们都是**静默失败**:

1. 网信办页面的属性**不加引号**(`href=//www.cac.gov.cn/...`)。期待 `href="..."` 的正则在满是链接的页面上返回零结果,看起来像「这页没有链接」。
2. 索引页翻过最后一页仍返回 **200 + 空列表**(不是 404)。翻页必须以「没有新链接」为终止条件,不能靠状态码。

## 三、三道自动闸(它们防的是什么)

| 闸 | 防什么 | 在哪 |
|---|---|---|
| **引文逐字比对** | 编造或记错条文 | `verify_quotes.py`,`validate.py` 调用 |
| **数量核对** | 引文对但摘要里的数字写错(「20 个工作日」→「200 个工作日」) | `validate.py` |
| **标题一致** | URL 打开是门户首页却当成文档存了下来 | `validate.py` |

**为什么是脚本不是人工复核**:引文在不在文件里是可判定的。可判定的事情就该判定,而不是拿去问人或问模型——后者会把要防的失误重新引进来。

三道闸都做过负向测试(故意写错一条,确认它会拦)。改闸之后请重做一次,别只看它「跑绿了」。

## 四、口径冲突怎么处理

**并列保留,标明哪条现行,不要删旧的。**

法规会改。已经踩到两次:
- 数据出境安全评估结果有效期从 **2 年**改成 **3 年**(2024 年规定改的);
- 标准合同路径的出境量区间从「不满 10 万人」改成「10 万人以上、不满 100 万人」,起算基准从「上年」改成「当年」。

两处的旧条文都还在 `data/obligations.csv` 里,标 `status=superseded` 并在 `conflict_note` 写清被什么取代。**删掉会让「规则变过」这件事消失**,而正是这件事会让照旧条文办事的人出错。

同一个数字属于不同统计期间时同样并列(例:「1100 余款」在 2025 年度报告和 2026 年专项行动通报里都出现,期间不同、可能重叠、不可相加)。

## 五、什么不进库

- 没有官方出处的内容;二手报道可引用,但关键事实必须回到一手原文
- 专家解读、宣讲会动态、图解页——它们不产生可执行义务,收进来只降低信噪比
- 门户首页快照(内容天天变,没有留存价值)
- 未脱敏的个人信息或企业敏感数据

## 六、已知局限(别当它不存在)

- **标准正文未归档**:GB/T 43697-2024 与 GB/T 45654-2025 只归档了标准平台的检索条目页,含标准号与发布/实施日,**不含条文**。涉及标准条款的表述一律标 ⚠️。
- **广泛流传的量化阈值未经核实**:GB/T 45654 的「不良信息比例 ≤5%」「合格率 ≥90%」在本库无任何归档佐证,不要直接写进产品验收线。
- **部分名单以图片发布**:合规审计认证机构两批名单的逐家机构名称在原文中是图片,纯文本归档只留下了数量。
- **少数条目仍标 ⚠️**,每条都写明了性质;能自己查的写了查法。

## 七、时间口径

一律**北京时间(Asia/Shanghai, UTC+8)**。脚本已固定该时区,不要改成 UTC 或运行机器的本地时区。
